# Convergence artifacts — what every run leaves behind

Every run leaves **durable, re-readable state** that makes the next run cheaper — this is what
makes the process convergent. All are **files in the repo** (travel with the codebase,
AI-navigable), never memory.

| Artifact | Path | Lifespan | Role |
|---|---|---|---|
| Campaign file | `docs/architecture/campaign.md` | persistent | The thin **project-parameters** file (this skill holds the recipe; this file holds everything project-specific) |
| Domain glossary | `CONTEXT.md` (repo root) | persistent | **Vocabulary stability** across runs |
| Decision records | `docs/adr/NNNN-slug.md` | persistent | **Rejection memory** — the single most important convergence lever |
| Whole-game map | `docs/architecture/system-map.md` | persistent, **regenerated** each run | The **living truth** + the re-run baseline |
| Friction reports | `docs/architecture/runs/<date>-<phase>-review.html` | **archived, frozen** | Point-in-time history; never current truth |

## campaign.md — the project-parameters file

Created at campaign start. Holds *only* what is project-specific (everything else lives in this skill):

- **Goal + the two drivers** with the named **anchor tasks** (kept honest — real features the
  project actually wants next, not invented exercises).
- **Pre-labeled population tables** — modules sorted into A/B/C/D with one-line rationale each
  ("pure data + math, no Node deps" / "reaches up via `get_parent().facing`" / …).
- **Expected candidates** — a head-start list for Phase 1, explicitly *not pre-decided*.
- **Run log** — one line per completed phase/dive (date, commit, verdict) so a fresh session can
  orient without replaying history.

## CONTEXT.md — domain glossary

Format: `domain-modeling/CONTEXT-FORMAT.md` (opinionated; 1–2 sentence what-it-IS definitions;
`_Avoid_:` synonym bans; project-specific terms only). Campaign additions that have proven out:

- **Deep-reference pointer**: entries carry a `§N` tag into the project's deeper design doc(s)
  instead of duplicating them; terms with no tag are explicitly "not yet in that doc".
- **Methodology-vocabulary disclaimer**: process terms (seam, populations A–D, depth-as-leverage,
  deletion test) live in this skill, **not** in the glossary — say so in one line near the top.
- **Inline status qualifiers**: `[dormant]`, "do-not-re-add decision", forward-provisioned — the
  glossary records *intentional inertness* so a re-run doesn't flag it as friction.

## ADRs — rejection memory

Format + the 3-gate creation test: `domain-modeling/ADR-FORMAT.md` (lazy; 1–3 sentences;
hard-to-reverse **and** surprising-without-context **and** real-trade-off). Campaign conventions on top:

- **Rejections are recorded as accepted decisions-not-to-do-X** ("keep X as-is — no Y wrapper");
  status stays `accepted` — the file's existence + title carries the verdict. No status lifecycle
  (a deliberate narrowing of ADR-FORMAT.md's optional `deprecated`/`superseded` values — in-place
  amendment replaces them).
- **Anti-re-raise clause** — close each ADR with an italic paragraph addressed to a future
  reviewer: "you will be tempted to re-suggest X; this is why not", plus what *would* justify
  revisiting (the supersede trigger). This clause is what makes re-runs converge.
- **Amendments append in-place** — a trailing `_Amended by <dive/date>: …_` italic paragraph on
  the same file stating what changed and what still stands. No separate file, no status flip.
- **ADRs are scope-fences for deep-dives.** Orient on `docs/adr/` *before* grilling a candidate;
  a dive must not contradict an ADR without surfacing the conflict for an explicit
  amend/supersede decision *before* the design thread locks. Sweep for **candidate-adjacent**
  ADRs, not just exact-name matches — an amendment may be owed to an ADR about a neighboring seam.

## system-map.md — the living map

Regenerated by each Phase-1 run (the "before vs after" of a campaign = `git diff` of this file
across the run's commits). Top matter: an italic preamble declaring it the committed re-run
baseline, pointing at `CONTEXT.md` (domain vocab) and this skill (methodology vocab), stamped
"Regenerated <date> by the Phase-1 survey of HEAD <sha>". Skeleton (numbered H2 sections):

1. **Orientation** — one dense prose paragraph: the whole architecture in glossary-faithful bold terms.
2. **Scene-tree map** — Mermaid `graph TD` of the static node/file tree (subgraphs for sub-scenes;
   dotted edges = runtime-instanced), plus a "load-bearing facts" prose note.
3. **Runtime data flow** — Mermaid `graph LR`, producer/consumer subgraph clusters, edges labeled
   signal vs call vs poll, plus directionality invariants in prose.
4. **Frame order** — numbered list: bolded step + exact `file.gd:line` ref + *why it must be in
   that position*; trailing "do not simplify" notes citing the governing ADR.
5. **Signals + script dependencies** — two tables: custom signals (Signal | Emitter | Payload |
   Connector→effect) and caller→callee wiring mechanism (signal / typed call / injected-path poll).
6. **Module populations table** — a legend defining A/B/C/D + "depth = verdict against the
   interface (leverage), not implementation size", then Module | Files | Lines | Pop. | Depth |
   one-line verdict, each row citing its governing ADR. Packaging blockers for A-modules; residual
   implicit-interface notes for B.
7. **Friction summary** — the headline convergence count ("N raw → deduped → M ADR-suppressed →
   K survived; X high / Y medium / Z low"), a pointer to the frozen run report for detail, and the
   ranked candidate list (what/why, line refs, a tag: worth-exploring / speculative / log-level).
   Sub-section **7.1 anchor-task ledger**: walk the anchor tasks step-by-step to prove the
   blast-radius claim; flag deliberate inert-by-design traps.
8. **Wiring-coupling inventory** — scene-node-name couplings bucketed by the axis *silent vs loud
   failure on rename*: Guarded (fail-loud / test-pinned) / Residual / Logged-only-accepted, each
   citing guard mechanism + pinning test + ADR.
9. **How to re-run** — points at this skill's PHASES.md kickoff prompts (use verbatim), names
   Phase-0 `CONTEXT.md` as prerequisite.

Conventions throughout: **bold = glossary term**; inline `(ADR-NNNN)` citations; `file.gd:line`
refs; explicit "dormant / deferred / by design" qualifiers so intentional gaps are not re-flagged.

## runs/ — frozen history

The Phase-1 survey generates its HTML report (format: [HTML-REPORT.md](HTML-REPORT.md)) to `$TMPDIR` by
design — nothing lands in the repo. This campaign **adds an archive step**: copy each report to
`docs/architecture/runs/YYYY-MM-DD-<phase>-review.html`, frozen.

- Each archived report carries an **"as-of <date>, not maintained truth"** banner.
- `runs/README.md` shape: a blockquote banner stating the frozen-snapshot rule ("a report named a
  module the worst offender *on its date*; it may since be refactored — never read an archived
  report as current state"); a three-way truth pointer (**living** = `system-map.md` · **settled**
  = `docs/adr/` · **frozen** = here); an index table (Date | Report | Notes: candidate count,
  rec #1, refutations→ADRs, convergence verdict).
- This is a real trade-off (run history & before/after legibility **vs** zero-stale-doc surface) —
  archiving reverses the engine's ephemeral-only default, so **record the project's choice as an
  ADR** when adopting it.
